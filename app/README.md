# memory-diary app

Android client. Login (passphrase → session JWT, stored in `flutter_secure_storage`), a box
to tell it new facts or corrections, and a searchable list of what's stored. No secret is
compiled into the app — only the Worker's public base URL.

## Why there's no `android/` folder committed

This project's `android/` platform scaffold is **generated by CI**, not committed —
`.github/workflows/build-apk.yml` runs `flutter create --platforms=android .` before
building, which fills in a fresh `android/` matched to whatever Flutter version that
workflow run installs, without touching `lib/` or `pubspec.yaml` (this is Flutter's own
supported way to retrofit a platform onto an existing project). That was a deliberate
choice here, not an oversight: this repository was built without a local Flutter
installation and without free disk space to install one, so there was no way to generate
and verify Gradle/Kotlin/AGP-version-matched platform files locally. Regenerating in CI
guarantees the versions always match the Flutter SDK actually doing the build.

If you do have Flutter locally and want to develop with a persistent `android/` folder
(e.g. to open in Android Studio), run the same command yourself — it's safe to do more
than once:

```
flutter create --platforms=android --project-name=memory_diary --org=com.harithkavish .
```

## Run it

```
flutter create --platforms=android --project-name=memory_diary --org=com.harithkavish .
flutter pub get
flutter run --dart-define=API_BASE_URL=https://<your-worker>.workers.dev
```
